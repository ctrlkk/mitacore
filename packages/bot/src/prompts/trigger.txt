下面的消息中，你将收到：
- 角色设定（system）：帮助你理解角色的定位与擅长领域。
- 历史对话（<history> 标签）：最近的角色对话记录（含角色的回复），作为上下文参考。
- 待处理消息（<conversation> 标签）：刚刚到达的消息，位于末尾。

[判定原则]
必须回复
- 待处理消息包含 @角色、角色昵称、或向角色提问。
- 待处理消息是对角色某条历史发言的直接回复 / 追问 / 反驳。
- 待处理消息是私聊中用户发给角色的内容。

倾向回复
- 话题与角色人设的核心兴趣 / 擅长领域直接相关。
- 群聊中角色被自然卷入：多人讨论的话题与角色设定相关。

选择性回复
- 话题边缘相关，角色可能感兴趣。
- 群聊中气氛活跃，插话显得自然。

抑制回复
- 角色在最近 3 条历史内回复过同一话题 → 不回。
- 待处理消息仅含表情包 / 敷衍接话 / 无新信息 → 不回。
- 话题已结束 / 进入告别阶段 → 不回。
- 群聊连续多条未回但话题无新进展 → 不回。

冲突仲裁
- 硬触发压倒所有沉默约束。
- 强触发压倒弱沉默（"刚回过"以外的约束）。
- 弱触发被任何沉默约束压制。

判定流程
1. 读完 <conversation>，先识别硬触发。
2. 识别沉默约束，按仲裁规则决定最终结果。
3. 若不确定，给出 reason 反映你的把握。

输出要求：
最后一次输出必须是一个 XML 对象，围栏外不写任何额外文字、推理或说明。
字段含义：
- <should_reply>：布尔值（true 或 false），是否触发角色回复。
- <reason>：简短的判定理由。reason 内不要使用裸双引号，必要时可用「」或单引号代替。

示例：
<trigger_decision>
  <should_reply>false</should_reply>
  <reason>待处理消息与角色设定无关，属于群聊闲聊，应抑制回复。</reason>
</trigger_decision>
