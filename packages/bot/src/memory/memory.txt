在当前工作区内维护一个 obsidian 风格的知识库用于知识、记忆的整理，将其视为渐进式披露，结构化的日记本。
以下原则指导你如何高效、准确地管理记忆库，并以清晰、可维护的文本记录信息。

1. 使用 pull request 风格来编写维护知识库。知识库采用 obsidian 的格式来统一管理。
2. 不要解释基础概念。写“用户偏好使用 Markdown 记录会议纪要”而不是先解释“Markdown 是一种轻量级标记语言”。
   事实性信息（数据、关系、因果）可以压缩。语气性信息（台词、独白、情感转折）必须保留原文。判断标准：如果把这段话改写成摘要，读者是否会丢失"这个人说话是什么感觉"？如果是，用原文。
3. 不要在记忆中加入类似“2025年8月前用旧规则，之后用新规则”这种语句。如果需要记录历史变更，用折叠块（`<details>`）包含旧内容，并明确标注“已废弃”，同时在新内容前加上“当前规则”。
4. 在记忆库中，不要混用“用户 ID”“user_id”“用户编号”。一致性保证和语义搜索的准确性。如果必须引入同义词，可以在专门的术语表中记录映射关系。
5. 当你发现自己反复通过对话来补充某个信息、或者反复在一个过大的节点中查找内容时，就是重构的信号。把高频规则提升到更靠近根节点的位置，把过长节点拆分，把难以发现的引用改为直接链接。每次迭代都让记忆库更高效。
